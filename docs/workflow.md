# Правила работы с репозиторием

Короткая версия — в `AGENTS.md`, здесь подробнее.

## Что коммитим

- **Одно законченное изменение — один коммит.** Собрал, проверил, закоммитил. Не копим правки за день.
- Незаконченное не коммитим в `main`: либо доделываем, либо ветка `wip/<тема>`.
- Перед коммитом сборка обязана проходить: `gradle assembleDebug` (см. «Сборка»).
- Проверку в эмуляторе/на приставке пишем в теле коммита: что именно видели. Если не проверяли — так и пишем.

## Чего в репозитории быть не должно

- `build/`, `.gradle/`, `*.apk` — артефакты сборки (уже в `.gitignore`).
- `local.properties` — там путь к SDK и ключ TMDB. Он у каждого свой, в git не попадает.
- Скриншоты и логи проверок — держим вне репозитория (`build/` и так игнорируется).
- Чужие незавершённые правки. Если в проекте работает вторая сессия/человек:
  `git status` перед работой, `git add <свои файлы>` вместо `git add -A`, чужое не перезаписывать.

## Сообщение коммита

```
область: что сделано

Зачем это нужно и что проверено (эмулятор / приставка / не проверено).
```

- Заголовок до 72 символов, без точки в конце, в повелительном наклонении: «добавить», «убрать», «починить».
- Области: `торренты`, `карточка`, `плеер`, `настройки`, `каталог`, `источники`, `сервисы`, `логотип`, `сеть`, `история`, `сборка`, `доки`.
- Пример: `торренты: всплывашка «TorrServe не установлен» и поле адреса`.

История читается сверху вниз: по заголовкам должно быть понятно, что менялось, без открытия диффа.

## Ветки и теги

- `main` — состояние, которое собирается и работает.
- Эксперимент, который может не взлететь — `feature/<тема>`, потом merge в `main` после проверки.
- Проверенную сборку помечаем тегом: `git tag -a v0.2-2026-11-03 -m "проверено в эмуляторе"`. Так можно вернуться к рабочему состоянию.

## Сборка

```powershell
$env:JAVA_HOME='<JDK 17>'
& '<Android SDK>\gradle-8.7\bin\gradle.bat' -p <проект> assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk` (в git не попадает).

Обновление убивает процесс, и Android сам приложение не открывает. Поэтому после установки сразу открываем его:

```powershell
adb -s emulator-5554 install -r app\build\outputs\apk\debug\app-debug.apk
adb -s emulator-5554 shell am start -n ru.lazytv/.MainActivity
```

## Что писать в PLAN.md

`PLAN.md` — что сделано и чем проверено, `plan_future.md` — что осталось, `docs/not-doing.md` — что не делаем и почему. Коммит, меняющий поведение, обновляет `PLAN.md` тем же коммитом.

## Пробные данные для нового экрана (2026-11-03)

Новый экран или список не заставляем владельца набирать данные руками: после установки сборки сразу заполняем настройку пробными данными (только debug-сборка, приёмник `DebugSeed`).

```
adb -s emulator-5554 shell "am broadcast -a ru.lazytv.SEED -n ru.lazytv/.DebugSeed --es key search_history --es value '[\"матрица\",\"дюна\"]'"
```

Ключи берутся из констант `Settings` (`search_history`, `history` и др.), значение пишется как есть. Экран читает настройки при показе: открыть его заново. В Git Bash перед командой задать `MSYS_NO_PATHCONV=1`.
