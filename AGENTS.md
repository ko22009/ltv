# LazyTV — памятка для агентов и людей

Android TV приложение на Kotlin (Leanback + ExoPlayer): каталог TMDB, списки, видеосервисы, поиск,
торренты через TorrServe, встроенный плеер. Подробности — `PLAN.md`, планы — `plan_future.md`,
что не делаем — `docs/not-doing.md`, правила git — `docs/workflow.md`.

## Сборка

```powershell
$env:JAVA_HOME='<JDK 17>'
& '<Android SDK>\gradle-8.7\bin\gradle.bat' -p <проект> assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Эмулятор: `adb -s emulator-5554`, приставка: `<приставка>:5555`.
После установки приложение открывать сразу: `adb -s emulator-5554 shell am start -n ru.lazytv/.MainActivity`. Android после обновления сам его не запускает.

## Коммиты

- Одно законченное изменение — один коммит. Сначала сборка, потом коммит.
- Заголовок: `область: что сделано` (до 72 символов). Области: торренты, карточка, плеер, настройки,
  каталог, источники, сервисы, логотип, сеть, история, сборка, доки.
- В теле — зачем и что проверено. Не проверено — так и написать.
- Незаконченное — в ветку `wip/<тема>`, не в `main`.
- Проверенную сборку помечать тегом: `v0.2-YYYY-MM-DD`.
- `local.properties`, `build/`, `*.apk` в git не попадают.

## Если работают несколько человек/сессий сразу

- Перед началом: `git status`.
- Коммитить только свои файлы: `git add <файлы>`, не `git add -A`.
- Чужие незавершённые правки не перезаписывать; при сомнении — сначала коммит того, что было.

## Стиль кода

- Ничего не менять в чужом файле без необходимости; правки — точечные.
- Тексты для пользователя — по-русски, спокойные и короткие.
- Комментарии — по-английски, объясняют «зачем», а не «что».

## Дизайн-система (обязательно)

- Перед любым экраном или деталью интерфейса — `docs/design-system.md`. Карточки, плитки, кнопки, иконки,
  цвета и сетки берутся оттуда; свою копию «похожей» детали не делать (своя карточка в поиске и своя корзина,
  урок 2026-11-03).
- Нужной детали нет — расширить существующую или добавить новую в общий файл и **записать в `docs/design-system.md`
  в том же коммите**. Иконки только из Material или уже имеющиеся в проекте, новые не рисовать.
- После правки внешнего вида сравнить новый экран с соседним в эмуляторе: карточки, отступы и иконки должны совпадать.

## Визуал — только владелец (правило для DeepSeek)

- DeepSeek **не трогает внешний вид**: вёрстку, отступы, размеры, цвета, иконки и расположение деталей на экране.
  Визуальные косяки владелец исправляет сам (2026-11-03).
- Задача про экран для DeepSeek — это функциональность: данные, навигация, загрузка, поведение. Готовые детали
  дизайн-системы использовать можно, но «улучшать» и переделывать их нельзя.
- Заметил визуальную проблему — написать о ней в ответе, а не править.
- Это правило для DeepSeek важнее раздела «Дизайн-система»: остальным агентам и людям он по-прежнему действует.

## Общие правила владельца (для любого агента, 2026-11-03)

Взято из личных правил владельца: они действуют и для DeepSeek, и для других агентов.

**Работа**
- Перед правкой найти все такие же места (`Grep` по подписи, коду статуса, имени класса), а не только то, где просили. Ошибку чинить в причине (в общем месте), а не в симптоме.
- Сначала понять задачу и прочитать код. Нужно ли это вообще? Есть ли уже такая деталь в проекте? Не делает ли это платформа или подключённая библиотека? Только потом минимум кода. Слои и настройки «на потом» не создавать.
- Не упрощать проверку входных данных, обработку ошибок, где теряются данные, безопасность. Осознанное упрощение помечать комментарием `упрощено:` с пределом.
- Мелкие правки текстов и отступов: без полного набора проверок. Логика, база, безопасность, расчёты: проверки обязательны. Не повторять проверки на том же коде, если они уже прошли.
- В конце честно написать, что проверено, а что нет. Не писать «готово», пока не проверено.
- Серверы и SSH: только вход по ключу, пароли не подбирать, подключения не повторять в цикле, команды собирать в одно подключение. Защиту от ботов (капчи, Anubis) не обходить.

**Интерфейс на пульте (Android TV)**
- Сетка карточек только через `titleCardGrid` и `titleGridParams` (`Cards.kt`), кнопки только через `chipButton` (высота `CHIP_HEIGHT`). Высота карточки, скелетона и плитки одна и та же (`TITLE_POSTER_HEIGHT`, `TITLE_INFO_HEIGHT`), иначе ряд «прыгает» при прокрутке.
- Ширина колонки в сетке считается с промежутками и целыми пикселями, формула в `docs/design-system.md`. Выравнивание считать по коду, скриншоты не снимать, если владелец не просил.
- Ряд, который может не поместиться на экране, делать горизонтальной прокруткой. Стрелки пульта должны вести к ближайшему по смыслу элементу. Экран `BrowseSupportFragment` не передаёт фокус между соседями сам: переходы делать перехватом клавиш (`setOnKeyListener`, `setOnKeyInterceptListener`).
- После правки интерфейса собрать и поставить сборку в эмулятор (`adb -s emulator-5554 install -r`, устройств два). Новый экран сразу заполнять пробными данными через `DebugSeed` (команда в `docs/workflow.md`), чтобы владельцу не вводить их руками. Приставку без команды не трогать.

**Общение**
- По-русски, коротко и простыми словами (пример: «окно времени 10:00–12:00», не «слот»). Без длинных тире «—» в текстах для владельца и в текстах от его имени: точка, запятая, двоеточие или скобки.
- О себе безлично («добавлено», «проверено»). Вопросы только если ответ меняет решение; остальное закрыть разумным значением и сказать одной строкой.

**Windows (PowerShell 5.1, русская локаль)**
- Скрипт `.ps1` с кириллицей сохранять в UTF-8 с BOM или держать ASCII и передавать русские пути параметрами. `Get-Content`, `Set-Content`, `Import-Csv` с `-Encoding UTF8`. Пути в `-LiteralPath`, в одинарных кавычках.
- Многострочный код писать инструментами правки файлов, а не `heredoc` и `sed`. Python запускать `python -I -X utf8`, файлы открывать с `encoding='utf-8'`.
